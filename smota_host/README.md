# smOTA 上位机

这个目录是当前使用的 Python 图形上位机实现，和 `examples/win_sim/test_host.py` 已经分离。

当前实现基于 `tkinter`，用于通过 `TCP` 或 `Serial(USB CDC)` 执行 smOTA 升级流程。

## 当前能力

- 图形界面启动与操作
- OTA 文件选择，只允许 `.ota`
- `.ota` 内部可包含 `.bin` 或 `.hex`
- `.hex` 文件在主机侧解析为二进制镜像后再发送
- 支持 `TCP` / `串口` 两种传输方式
- 连接成功后，优先读取设备当前固件版本
- 目标版本从 `.ota` 内的 `manifest.json` 自动读取并只读显示
- 项目名称 ID 从 `.ota` 内的 `manifest.json` 自动读取并只读显示
- 版本一致时可自动跳过升级
- 支持强制安装
- 支持安装后激活校验
- 显示升级进度
- 显示主机侧运行日志
- 显示 `TX` / `RX` 协议帧摘要

## 启动

在仓库根目录执行：

```powershell
pip install pyserial
python -m smota_host
```

## OTA 文件规则

当前只允许选择以下格式：

- `.ota`

当前行为如下：

- 选择 `.ota` 时，主机先解压读取 `manifest.json`
- 主机会校验 `manifest.json` 的必要字段、内部固件文件存在性和固件 SHA-256
- `manifest.json` 中的目标版本会自动显示到界面
- `.ota` 内部若是 `.bin`，直接按原始二进制内容发送
- `.ota` 内部若是 `.hex`，主机先解析 Intel HEX，再生成连续二进制镜像发送
- 其他后缀会在界面中直接拦截

### `.ota` 容器结构

当前 `.ota` 文件本质上是 ZIP 容器，至少包含：

- `manifest.json`
- 一个固件文件（`.bin` 或 `.hex`）

当前 `manifest.json` 至少包含：

- `format_version`
- `firmware_name`
- `firmware_format`
- `firmware_size`
- `firmware_sha256`
- `project_id`
- `fw_version`

推荐使用仓库根目录的打包脚本生成：

```powershell
python scripts/pack_ota.py `
  --elf examples/stm32g0/app/MDK-ARM/stm32g0_single_slot_app/stm32g0_single_slot_app.axf `
  --firmware examples/stm32g0/app/MDK-ARM/stm32g0_single_slot_app/stm32g0_single_slot_app.hex `
  --output build/stm32g0_single_slot_app.ota
```

## 连接方式

界面中的“传输方式”决定显示哪一组连接参数：

### TCP

显示：

- 主机地址
- 端口

适用场景：

- 连接 `win_sim`
- 连接通过 TCP 转发的 OTA 服务

### 串口

显示：

- 串口号
- 串口波特率
- 刷新串口

适用场景：

- 连接真实设备的 USB CDC 虚拟串口

## 当前 OTA 流程

当前实际执行流程如下：

1. 建立连接
2. 先发送 `QUERY_VERSION(0x07)` 查询设备当前运行版本
3. 比较“当前运行版本”和“目标版本”
4. 如果版本一致且未勾选“强制安装”，则直接跳过升级
5. 如果版本不一致，或已勾选“强制安装”，进入升级流程
6. 发送 `HANDSHAKE`
7. 发送 `HEADER_INFO`
8. 分块发送 `DATA_BLOCK`
9. 发送 `DATA_COMPLETE`
10. 发送 `INSTALL`
11. 如果启用了“激活校验”，则等待设备重连并再次做版本确认

## 参数说明

下面只描述“当前代码中已经实现的真实效果”。

### 目标版本

作用：

- 不再手工填写
- 由 `.ota` 内 `manifest.json` 自动解析得到
- 用于和设备当前运行版本比较
- 用于决定是否跳过升级
- 会写入 `HANDSHAKE` 请求中的版本字段
- 安装完成后，激活校验会检查设备是否运行到了这个版本

对 OTA 行为的影响：

- 版本相同且未启用强制安装：跳过下载
- 设备当前版本高于目标版本且未启用强制安装：拒绝继续
- 启用强制安装时：即使版本相同或目标版本更旧，也继续升级

### 项目 ID

作用：

- 不再手工填写
- 由固件 `main_app` 中固化的项目名称生成
- 打包脚本会从 ELF 中读取后写入 `.ota` 的 `manifest.json`
- 主机从 `manifest.json` 自动读取并写入 `HANDSHAKE` 请求
- 主机侧会裁剪为最多 16 字节，不足补零

对 OTA 行为的影响：

- 当前主机一定会发送
- 当前设备会将其与本机固化的项目名称 ID 严格比对
- 不匹配时，握手阶段直接失败，避免把其他项目的固件下发到本设备

### 传输方式

作用：

- 决定本次升级使用 `TCP` 还是 `串口`
- 决定界面显示哪一组连接参数

对 OTA 行为的影响：

- `tcp`：使用 socket 连接
- `serial`：使用 `pyserial` 打开串口

### 主机地址

仅 `TCP` 模式可见。

作用：

- 作为 TCP 连接目标地址

对 OTA 行为的影响：

- 决定连接到哪台主机

### 端口

仅 `TCP` 模式可见。

作用：

- 作为 TCP 连接目标端口

对 OTA 行为的影响：

- 决定连接到目标服务的哪个端口

### 串口号

仅 `串口` 模式可见。

作用：

- 指定要打开的串口设备，例如 `COM5`

对 OTA 行为的影响：

- 串口为空时不允许启动升级

### 串口波特率

仅 `串口` 模式可见。

作用：

- 作为串口连接参数传给 `pyserial`

对 OTA 行为的影响：

- 必须与设备侧串口配置一致，否则通信失败或数据异常

### 分块大小

作用：

- 影响每次 `DATA_BLOCK` 请求携带的固件字节数

当前实现细节：

- 主机不会盲目使用这个值
- 实际发送大小为：
  - `min(分块大小, 设备握手返回允许的最大包长 - DATA_BLOCK 头长度)`

对 OTA 行为的影响：

- 值越大，理论上发送效率越高
- 值过大不会直接越界，主机会被设备的 `max_packet_size` 限制住

### 通信超时(s)

作用：

- 用于底层通信超时

当前实现细节：

- `TCP`：作为 socket 超时
- `串口`：作为串口读写超时

对 OTA 行为的影响：

- 值太小：容易在链路抖动时误判超时
- 值太大：出错后等待更久才返回

### 连接超时(s)

作用：

- 控制主机尝试连接设备的总时长

当前实现细节：

- 主机会循环尝试连接，直到超时
- 安装后等待设备重连时，也会再次使用连接重试逻辑

对 OTA 行为的影响：

- 值太小：设备尚未准备好时可能直接报连接失败
- 值太大：异常时等待更久才退出

### 分块超时(ms)

作用：

- 写入 `HANDSHAKE` 请求中的 `block_timeout_ms`

当前实现状态：

- 主机侧不会单独按这个值控制每个分块发送超时
- 设备侧可以把它当作“数据包间超时建议值”使用

对 OTA 行为的影响：

- 主要影响设备侧
- 在当前仓库的设备实现中，这个值会进入运行时上下文并参与包间超时判断

### 校验超时(ms)

作用：

- 写入 `HANDSHAKE` 请求中的 `check_timeout_ms`

当前实现状态：

- 主机侧当前没有基于它建立独立的校验阶段计时器
- 设备侧当前也没有完整落实成单独的“校验超时控制”

对 OTA 行为的影响：

- 目前主要是协议字段保留
- 当前实际影响很弱

### 安装超时(ms)

作用：

- 写入 `HANDSHAKE` 请求中的 `install_timeout_ms`

当前实现状态：

- 主机侧安装完成后，会用它来估算“等待设备重连”的时间上限
- 计算方式为：`install_timeout_ms / 1000 + 5` 秒

对 OTA 行为的影响：

- 直接影响安装后等待设备重新上线的时长
- 值太小：设备还没重启完成就被主机判失败
- 值太大：设备失联时主机会多等一段时间

### 总超时(ms)

作用：

- 写入 `HANDSHAKE` 请求中的 `total_timeout_ms`

当前实现状态：

- 主机侧当前没有实现“整个 OTA 任务总超时”计时器
- 设备侧当前也没有完整实现基于它的总流程超时控制

对 OTA 行为的影响：

- 当前主要是协议字段保留
- 目前实际影响很弱

### 强制安装

作用：

- 改变版本比较后的决策
- 安装请求里会把 `force_install` 标志置位

对 OTA 行为的影响：

- 勾选后：
  - 版本相同也继续升级
  - 当前运行版本高于目标版本也允许继续
- 不勾选时：
  - 版本相同直接跳过
  - 当前运行版本更高则拒绝继续

### 激活校验

作用：

- 控制安装后是否继续等待设备重连并确认新版本

对 OTA 行为的影响：

- 勾选时：
  - 安装后主机不会立即结束
  - 会等待设备重新上线
  - 会再次读取/校验当前运行版本
- 不勾选时：
  - 安装请求成功后，主机直接结束流程

## 参数中哪些是“真正生效”的

### 当前主机侧明确生效

- 目标版本
- 传输方式
- 主机地址
- 端口
- 串口号
- 串口波特率
- 分块大小
- 通信超时(s)
- 连接超时(s)
- 安装超时(ms)
- 强制安装
- 激活校验

### 当前会发送给设备，但主机侧没有完整落实

- 分块超时(ms)
- 校验超时(ms)
- 总超时(ms)

其中：

- `分块超时(ms)` 在当前仓库设备实现中已经比另外两个更“有效”
- `校验超时(ms)` 和 `总超时(ms)` 目前更偏向协议预留字段
