# smOTA 当前代码协议说明

> **文档性质**：按当前仓库代码反推  
> **文档版本**：v2.1  
> **编写日期**：2026-04-30  
> **适用范围**：当前 `smota_host` 主机实现、`smota_core` 协议处理实现、`examples/stm32g0_single_demo` 端口实现

## 1. 概述

当前 smOTA 通讯协议是一套运行在 `TCP` 或 `串口` 之上的自定义二进制帧协议。

`.ota` 是主机本地 ZIP 容器，设备不会接收 ZIP，也不会解析 `manifest.json`。设备只接收主机提取后的目标固件信息、固件数据和校验信息。

## 2. 通用帧格式

字节序为小端，协议边界由 `SOF` 和 `Length` 确定。

```text
+--------+-----+--------+---------+-------+
| SOF    | Cmd | Length | Payload | CRC16 |
+--------+-----+--------+---------+-------+
| 5 Byte | 1   | 2      | N       | 2     |
+--------+-----+--------+---------+-------+
```

- `SOF` 固定为 ASCII `"smOTA"`。
- `Cmd` 为命令字，请求命令范围为 `0x01` 到 `0x04`。
- `Length` 为 Payload 长度，小端。
- `CRC16` 使用 CRC-16-CCITT，多项式 `0x1021`，初始值 `0xFFFF`，计算范围为 `SOF + Cmd + Length + Payload`。
- 响应命令统一为 `req_cmd | 0x80`。

```c
struct smota_frame_header {
    uint8_t sof[5];
    uint8_t cmd;
    uint16_t length;
};
```

## 3. 命令与 Payload

| 命令码 | 名称 | 方向 | 说明 |
|:--|:--|:--|:--|
| `0x01` | `QUERY` | 主机 -> 设备 | 携带目标版本和目标项目 ID，请求设备裁决是否允许升级 |
| `0x02` | `START` | 主机 -> 设备 | 开始升级，携带固件大小、SHA-256 和分块超时 |
| `0x03` | `DATA` | 主机 -> 设备 | 顺序发送固件数据块 |
| `0x04` | `FINISH` | 主机 -> 设备 | 通知传输完成，设备校验、标记 App 有效并复位 |

### `QUERY`

```c
struct smota_query_req {
    uint8_t fw_version_major;
    uint8_t fw_version_minor;
    uint8_t fw_version_patch;
    uint8_t flags;          /* bit0: 强制升级 */
    uint8_t project_id[16];
};

struct smota_query_resp {
    uint32_t error_code;
    uint8_t allow_upgrade;
    uint8_t fw_version_major;
    uint8_t fw_version_minor;
    uint8_t fw_version_patch;
    uint8_t project_id[16];
};
```

`QUERY` 是升级准入入口。主机必须把 `.ota` 中目标固件的版本和项目 ID 放入请求。设备返回当前运行版本、当前项目 ID，以及是否允许升级。

允许升级条件：

- `error_code == 0`
- `allow_upgrade == 1`

设备端准入规则：

- `flags.bit0` 置位时，设备跳过项目 ID 和版本判断，直接返回允许升级。
- 当前身份为 `0.0.0 + SMOTA_BOOT` 时，视为空 boot，允许任意非空目标项目 ID。
- 非空 boot 时，目标项目 ID 必须等于当前项目 ID。
- 如果启用 `SMOTA_RELIABILITY_VERSION`，非空 boot 还会执行版本准入校验。
- `QUERY` 放行后，设备缓存目标版本和目标项目 ID，后续 `START` 必须基于这次放行继续。

### `START`

```c
struct smota_start_req {
    uint8_t flags;          /* bit0: sha256 有效 */
    uint32_t firmware_size;
    uint8_t sha256_hash[32];
    uint16_t block_timeout;
};

struct smota_start_resp {
    uint32_t error_code;
    uint16_t max_payload_size;
};
```

`START` 只能在一次允许升级的 `QUERY` 之后发送。设备检查固件大小，擦除 App 区，并使用 `QUERY` 缓存的目标版本作为本次待安装版本。当前 `max_payload_size` 返回 `256`，其中包含 `DATA` 请求头。

### `DATA`

```c
struct smota_data_req {
    uint32_t offset;
    uint16_t length;
    uint8_t data[];
};

struct smota_data_resp {
    uint32_t error_code;
    uint32_t received_offset;
};
```

设备只支持顺序写入，`offset` 必须等于当前累计接收长度。主机实际固件分块大小为：

```text
min(用户配置分块大小, START 响应 max_payload_size - sizeof(struct smota_data_req))
```

### `FINISH`

```c
struct smota_finish_req {
    uint32_t total_size;
};

struct smota_finish_resp {
    uint32_t error_code;
    uint16_t reset_delay_ms;
};
```

设备检查 `total_size` 和累计接收长度是否等于 `START.firmware_size`。如果 `flags.bit0` 有效且设备配置开启 SHA-256 校验，则重新读取 App 区并校验 hash。成功后回复 `FINISH_RESP`，随后复位。复位后 Boot 进入 500ms 捕获窗口，窗口内无有效报文且 App 有效时跳转 App。

## 4. 状态机与流程

设备状态流转：

```text
IDLE -> STARTED -> TRANSFER -> FINISHED -> reset
```

主机升级流程：

```text
QUERY(target version/id) -> START -> DATA... -> FINISH -> 可选重连 QUERY(target version/id)
```

`QUERY` 可用于 boot 捕获窗口。`START/DATA/FINISH` 任一失败后，设备会重置当前 OTA 会话。

## 5. 线上错误码

所有响应中的 `error_code` 使用统一枚举：

| 值 | 名称 |
|:--|:--|
| `0` | `OK` |
| `1` | `INVALID_STATE` |
| `2` | `INVALID_PARAM` |
| `3` | `PROJECT_ID_MISMATCH` |
| `4` | `VERSION_REJECTED` |
| `5` | `FLASH_INSUFFICIENT` |
| `6` | `FLASH_WRITE_FAILED` |
| `7` | `VERIFY_FAILED` |
| `8` | `LENGTH_ERROR` |

## 6. `.ota` 本地容器

`.ota` 仍是 ZIP 容器，至少包含：

- `manifest.json`
- 一个 `.bin` 或 `.hex` 固件文件

`manifest.json` 至少包含：

- `format_version`
- `firmware_name`
- `firmware_format`
- `firmware_size`
- `firmware_sha256`
- `project_id`
- `fw_version`

主机解析 `.ota` 后校验固件 SHA-256，再把目标版本、项目 ID、固件内容和 hash 通过 `QUERY/START/DATA/FINISH` 协议发送给设备。

## 7. 当前特性与限制

- 保留固定 SOF、CRC16、变长 Payload、请求/响应命令字。
- 保留设备端升级准入、顺序分块传输、完成校验、安装后复位、串口/TCP 承载。
- 不支持断点续传。
- 不支持协议分片。
- 不做响应序号管理。
- 主机侧强制升级通过 `QUERY.flags.bit0` 表达，最终是否允许升级仍由设备端 `QUERY` 应答表达。
